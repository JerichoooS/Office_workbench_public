# 个人工作台 · 开发规范（v2）

> 给任何来维护本项目的人或 AI（包括 WorkBuddy）。**动手前先读完本文件**；改动要符合这里的约定，改了约定就同步改本文件。
> 需求有不清楚的地方，**先问用户，确认后再写代码**。

---

## 1. 项目是什么

个人工作管理应用：**任务（大）→ 待办（小）**，加上提醒推送、等待催办、材料收集。电脑和 iPhone 都要好用。

| 项目 | 约定 |
|---|---|
| 运行 | `node server.js`，零依赖，单端口（`PORT` 环境变量，默认 3000） |
| 部署 | WorkBuddy Sites；`installCmd` 留空，`startCmd` = `node server.js` |
| 登录与数据 | WorkBuddy Cloud SDK（`public/vendor/workbuddy-cloud-sdk.global.js`）：微信扫码登录 + 云数据库 |
| 前端 | 原生 ES Modules，**没有构建步骤、没有框架、没有 npm 包** |
| 外部资源 | **禁止**引用 CDN（jsDelivr、Google Fonts 等在国内不可靠）。第三方文件一律放 `public/vendor/` |
| 线上地址 | 部署后由 WorkBuddy 分配（`public/config.js` 中的 endpoint） |

## 3. 启动与本地调试

1. 本机运行：Mac 双击 `start-mac.command`，或 `node server.js`，打开 http://127.0.0.1:3000/
2. 地址是 `127.0.0.1` / `localhost` 时**自动进入本地模拟模式**：免登录、数据存浏览器 localStorage，页面顶部有「本地模拟模式」标记。
   - 首页空库时有「填充示例数据」按钮；设置页可「清空模拟数据」。
   - `?mock=0` 关闭模拟（会记住），`?mock=1` 恢复。
3. 线上域名永远不会进入模拟分支（判断在 `boot.js` 的 `isLocal`）。
4. 微信登录只能在线上地址测试（WorkBuddy 不允许本地回调）。

5. 本机运行时**不发推送**（HOST 是 127.0.0.1 / localhost 时不读口令、不启动推送调度），避免和线上抢提醒；确需在本机测推送：`WB_PUSH=1 node server.js`。
6. 模拟弱网：浏览器控制台 `WBMock.offline(true)`（所有查询返回网络错误），`WBMock.offline(false)` 恢复。

**改完代码的自检（每次都做）：**
- `node --check` 检查改过的 JS 文件；
- 本地模拟模式下，手机宽度（390px）和电脑宽度（1440px）各点一遍改动涉及的页面；外观相关的改动再用「现场模式」（大字号）看一遍；
- 浏览器控制台无报错；页面没有横向滚动。

## 4. 数据层规范

- **视图和组件不直接调用 `cloud.database`**，一律通过 `data/repos/*.js`。
- 仓储函数用 `run(builder)` 执行查询：出错会自动弹出中文提示并抛错（`err.handled = true`）。
  - 弱网：凭证因断网刷新失败时不发请求（否则会带着匿名身份读到空列表，看起来像数据丢了）；15 秒没回应算超时；网络类错误统一 `err.code = 'WB_OFFLINE'`，同步状态变「网络不稳定」，每 30 秒自动重试读取，恢复后变回「已同步」。
  - 读失败：保留当前画面（`main.js` 的 `show()` 不清空页面；切到新页面时显示「重试」）。写失败：明确提示「刚才的修改没有保存」；写超时提示「没能确认是否保存」。用户操作的 catch 里调用 `saveFailed(e)`。
  - 可能很多行的表用 `runAll(() => 查询)` 分页读完（平台可能限制单次返回行数，超出部分会被悄悄截掉）。`listTodos` 已经这样做。
- 根据界面上的旧行算改动（子步骤、标签、等待对象）用 `todos.updateTodoWith(id, row => patch)`：在排队里读最新行再算，两处同时改不会互相覆盖。
- 写操作完成后调用 `changed('表名')`，当前页面会自动刷新（保持滚动位置）。
- 状态流转等有副作用的逻辑写在仓储里（例：`todos.setStatus` 负责写完成时间、生成下一次重复、排催办），视图只调用。
- 库里的枚举值用英文（`todo/doing/waiting/done`），界面文字一律从 `data/schema.js` 取中文。
- 每张业务表都有 `owner_id`，类型是 **text**（WorkBuddy 云库的 `auth.uid()` 返回 text，不是 uuid），默认 `auth.uid()`，并开启 owner-only RLS；前端**不要**手动传 `owner_id`。
- **预料之中的错误**（如唯一约束冲突 23505）用 `run(builder, { expect: ['23505'] })`：不弹提示、不改同步状态，错误带 `expected = true`，由调用方处理。
- **新功能跟着数据库版本开关**（`data/features.js`）：启动时读 `wb_schema_version()`，`phase2()` = 云库执行过 005。依赖新表、新字段的功能都先判断它；没执行时功能不出现，其余照常可用（前端先上线、数据库后改也不会出错）。本地模拟可用 `WBMock.schema(['001','002','004'])` 测「还没执行 005」。

### 4.1 数据表一览（详见 `db/migrations/001_init.sql`）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `user_settings` | 每人一行设置 | 早/晚报开关与时间、默认提醒、AI 总开关与 Key、`ai_features`（各项 AI 功能开关，004 迁移） |
| `contacts` | 联系对象 | `kind`：person 人 / department 部门 / section 科室 / unit 单位 |
| `tasks` | **项目**（界面名称） | 起止日期、状态、`archived_at`（非空=已归档）、`source_task_id`（套用来源） |
| `task_contacts` | 项目-联系人 | 多对多 |
| `todos` | 待办（小） | `status`、`priority`(0=P0)、`due_at`+`due_all_day`、`waiting_on`、`repeat_rule`、`checklist`、`tags`、`client_id`（005：前端生成，同一用户内唯一，重发不重复） |
| `todo_logs` | 进展记录 | `kind`（005）：note 手写 / status 状态变化 / due 改期 / nudged 已催 |
| `reminders` | 提醒 | `kind`：before_due 截止前 / at_time 准时 / nudge 催办；`sent_at` 非空=已发送；005：`attempts` 重试次数、`retry_at` 下次重试、`failed_at` 重试用完仍没送达；每条待办最多一条待发催办（唯一索引） |
| `collections` / `collection_targets` | 材料收集 / 收集对象 | `submitted_at` 非空=已交 |
| `tags` | 标签库 | `use_count` 用于补全排序 |
| `push_subscriptions` | 推送订阅（每台设备一行） | |
| `trash` | 最近删除（005） | 删除待办 / 收集对象前由触发器自动存一份（`data`），30 天后自动清掉；删父行连带删除的不存 |
| `snapshots` | 每日云端快照（005） | 服务器每天每人一份（`day` 用户时区日期），`data` 与导出 JSON 的 `tables` 同格式；只留 14 天；用户只能读、删 |
| `schema_migrations` | 执行过哪些数据库改动（005） | 前端只能通过 `wb_schema_version()` 读 |

### 4.2 改表流程（必须按顺序）

1. 新建 `db/migrations/00N_说明.sql`（**不要改已执行过的旧文件**；唯一的例外是 001 开头的「防误跑」保护），一条语句一行块，语句之间空一行；新表要附 RLS 四条（模板见 `001_rls.sql`）。
   - **每个阶段的数据库改动合成一个文件**，用户只需要去 WorkBuddy 那台电脑交代一次。
   - 写成**可以重复执行**的（`IF NOT EXISTS`、`CREATE OR REPLACE`、`DROP … IF EXISTS` 再建）；最后一条把编号写进 `schema_migrations`。
   - 会因为已有数据失败的约束（如唯一索引）放进 `DO` 块里捕获，失败时提示并跳过，**不删用户数据**。
2. 同步改 `public/app/data/mock.js` 的 `DEFAULTS` / `FK`（字段默认值、级联关系），以及唯一约束 `UNIQUE`、触发器的模拟，否则本地模拟和线上行为会不一致。
3. 新枚举值写进 `data/schema.js`；依赖新字段的前端功能用 `features.js` 判断（见上）。
4. 在本文件 4.1 表格登记。
5. **数据库核对**：执行完用 `db/checks/` 里对应的只读核对查询确认改动齐全（例：`005_check.sql`，19 项应全部为 true）。
6. 部署前请 WorkBuddy **先把整个库导出一份留底**，再按编号执行新的迁移文件。

### 4.3 放心功能（第二阶段，都要求云库执行过 005）

- **删除可撤销**：删除待办 / 收集对象时，数据库触发器先存一份进 `trash`。删除后的提示条有「撤销」，用 `repos/trash.js` 按原 id 放回（进展一起放回，提醒只放回还没到时间的；项目、等待对象已经不在就置空）。放回两次不会变成两条（主键冲突 = 已放回）。
- **最近删除**（设置 › 数据与备份）：列出 30 天内删除的，可以放回；过期由数据库自动清掉。
- **云端快照**：服务器每天给每人存一份（`snapshots`，留 14 天，不含 AI Key），设置里可以下载（与导出 JSON 同格式）或直接「找回」。
- **从备份找回**（`data/restore.js`）：只补现在缺少的行，现有的一律不覆盖；按外键顺序、用原 id 插入；缺了上级的能置空就置空，不能的就不补；不碰设置。`planRestore` 是纯函数，用例在 `trust.test.mjs`。
- **没信号也能记**（`data/outbox.js`）：记一条遇到 `WB_OFFLINE` 先存本机（localStorage `wb-outbox`），联网后用同一个 `client_id` 补存，不会重复；同步状态点显示「N 条待同步」。只管记一条，离线打开整个工作台留到第四阶段。
- **提醒送达**：首页提示卡（`components/home-notice.js`，同一时间只出一张）在提醒重试 3 次仍没送达、或过了时间 10 分钟还没发出时提示；设置 › 通知与提醒有「提醒服务」一行，读 `/api/push/status`。
- **AI 打码**：发给模型的文字先把电话号码打码（`ai.js` 的 `maskPhones`），识别结果里再换回原号码；设置里有「数据去向」说明哪些内容会发给 DeepSeek。

## 5. 界面规范

**设计方向**：北欧冷淡风的暖色版本——低饱和、留白、功能入口清楚。参考设计稿 `design/prototype-v2.html`。

- 颜色、字体、圆角只用 `styles/tokens.css` 的变量；**组件里不写字面颜色**。深色模式由 tokens 自动切换。
- **配色（皮肤）**：`:root[data-skin]`，第一阶段三套：亚麻 linen（默认，不写属性）、宣纸 paper、现场 venue（高对比）。每套都有浅色、跟随系统的深色、手动深色三段，文字色按 WCAG 对比度求出（正文 ≥ 7，次要和最浅的提示字 ≥ 4.5）。新加一套：照 tokens.css 的格式复制三段，并在 `core/appearance.js` 的 `SKINS` 登记（含设置页小样用的 4 个颜色）。峡湾、陶土两套排在第三阶段，上线前先把标签改成中性色。
- **字号**：组件字号一律写 `calc(Npx * var(--fs))`；`data-font="large"` 时整体放大 1.125 倍。
- **外观只影响这台设备**：存 localStorage（`wb-theme-mode` 深浅、`wb-appearance` { skin, font, field }）。`index.html` 里的内联脚本在页面绘制前套用（启动不闪白），规则和 `core/appearance.js` 一致，改一处要两边一起改。「现场模式」= 现场配色 + 大字号。
- 状态色（完成、提醒、逾期、等待）各套配色都一样；状态一律同时配文字或图标，不能只靠红绿区分（色弱）。
- 只用系统字体（PingFang / 微软雅黑）。数字用 `.num`（等宽对齐）。
- 布局断点：**≤ 760px 为手机**（单栏 + 底部标签栏），否则为电脑（侧边栏 + 内容 + 右侧抽屉）。宽屏三栏（≥ 1280 详情常驻右栏）在第三阶段做。
- 悬停效果写在 `@media (hover: hover)` 里（手机上点过之后不会一直保持悬停色）。
- **列表行统一**（`components/todo-row.js`）：勾选圈可点范围 44×44；标题最多两行；等待中的显示「等 X · N 天 · 下次催 周五」；所属项目已归档时标「（已归档）」。所有列表的勾选都调用 `toggleDone()`：保存完成前不重复触发，完成后提示条带「撤销」（连同自动生成的下一次一起撤回）。
- 提示条 `toast(msg, { action: { label, onClick } })`：文字长会换行；带按钮时停留 5 秒。
- 不用浏览器 `alert / confirm / prompt`，用 `confirmSheet()`、`openSheet()`、`toast()`。
- 拼 HTML 时，**所有用户输入必须经过 `esc()`**。

**功能分级（用户确认，按使用频率摆放）：**

| 频率 | 功能 | 放在哪 |
|---|---|---|
| 每天多次 | 看今天、记一条、勾完成、改状态、记进展 | 首页、手机底部「+」、详情顶部 |
| 每周几次 | 看板、项目 | 主导航 |
| 偶尔 | 日历、材料收集、零星待办、全部待办（首页底部链接） | 首页右上角「日历」图标（底部弹出）；首页「负一屏」（从左往右滑或点左上角图标）；电脑侧边栏有「材料收集」 |
| 很少 | 推送、AI、联系人、外观、账号 | 设置页（分组列表 + 子页面） |

**首页标题行**：概览（负一屏）｜ 今天（日期旁是同步状态点）｜ ＋记一条（虚线圆圈，点开输入栏从下方展开）｜ 日历。
**首页分组顺序**：逾期 / 今天 / 等待他人 / 即将到期（折叠）/ 未定时间（超过 5 条时折叠）/ 今天完成（折叠）。
**负一屏**：搜索框在最上面；本周四个数字一行（可点开列表）+「写周报」；材料收集；零星待办；「查看全部待办」。
**导航**：手机底部 = 首页 / 看板 / ＋记一条 / 项目 / 设置（详情、负一屏打开时底部栏自动收起）；电脑侧边栏 = 搜索（Ctrl/⌘K）/ ＋记一条（N 键）/ 首页 / 看板 / 项目 / 日历 / 材料收集 / 全部待办 …… 设置、同步状态。从任何面板里点导航，会先关闭面板再跳转。
**设置结构**：`#/settings` 分组列表 →「通知与提醒」「AI 助手」（总开关 + 每项功能开关，模型/地址在「高级」）「常用联系人」（按使用次数排序，可编辑、删除、合并重复，`contacts.mergeContact`；删除前列出还在等这个人的待办，建议合并）「外观」（深浅 → 配色小样 → 现场模式 → 字号）「数据与备份」（同步状态、导出、工作台记什么）「账号与关于」子页面。
**待办详情顺序**：标题 → 状态 → 记一笔 + 最近 2 条进展 → 等待一行（拨打 / 换人）→ 截止（今天 / 明天 / 下周一）、提醒、项目、标签 → 子步骤 → 备注（网址、电话可点）→ 全部进展 → 更多设置（重复、优先级）→ 删除。改完一项不跳回顶部；「已保存」只在保存成功后提示。标题含「周报」的待办有「生成本周周报草稿」。
**动效**：点按缩放反馈、切页轻微上浮（数据刷新不触发）、面板滑入滑出；系统开启「减少动态效果」时全部关闭。

新功能先判断频率，再决定位置。

**常用组件类名**：`.btn(.primary/.small/.danger)`、`.chip(.accent/.wait/.bad/.warn/.ok/.ghost)`、`.seg`、`.switch`、`.list > .item`、`.group > .group-h`、`.card`、`.task-card`、`.placeholder`、`.form`、`.kv`、`.fold`。

**文案**：站在用户角度说话（「早报」不说「digest」）；按钮写清动作（「保存」「复制」），完成后 toast 说结果（「已保存」）；报错说清楚原因和怎么办。

## 6. 新增一个页面（步骤）

1. `public/app/views/xxx.js`，导出 `export async function mount(root, params, ctx)`：取数据 → `root.innerHTML = …` → 用 `root.onclick` 做事件委托。
2. `main.js` 里 `route('/xxx', xxx)` 注册。

## 7. 业务规则（已与用户确认，改动前先问）

- **命名与层级**（2026-10-20 调整）：**项目**（需要系统性追踪、全流程管理的工作，有起止时间、联系人）→ **待办**（具体要做的一件事）→ **子步骤**（待办里的检查项）。
  - 界面叫「项目」，数据库表和代码仍叫 `tasks` / `task_id`（避免迁移数据）；新写代码时注释里写「项目」。
  - 没归入项目的待办在「零星待办」（项目页顶部、负一屏），每条有「归入项目 ›」快捷按钮（`components/move.js`）。速记时没猜到项目会显示「放入零星待办」。
  - 「全部待办」是一个查看视图（独立页面 `#/all`，可搜索），入口在首页底部「查看全部待办」和负一屏；不放在项目页（用户 2026-10-20 反馈）。旧地址 `#/tasks?view=all` 自动跳到 `#/all`。
  - 待办详情顶部显示路径「项目 › 待办」。
- **看板**（用户确认 a+b+d+e）：默认展开「进行中」「等待他人」，「未开始」「已完成」收起；顶部项目标签筛选（含零星待办，放不下时右侧渐隐）；卡片显示项目、截止、「等 X · N 天」、子步骤进度；拖动换列改状态（手机长按 `LONG_PRESS_MS`=300ms 再拖，按住时卡片下沉提示；长按后不移动直接松手 = 弹出「移到…」菜单）；「已完成」列只显示近 `DONE_DAYS`=14 天；手机上列头吸顶；电脑上展开的列最窄 220px，放不下横向滚动，收起的列是竖条。配置集中在 `views/board.js` 顶部。
- **只记进展**（2026-10-22 确认）：工作台记待办、进展、联系人、电话、链接；**不放**文件、照片、网络参数、公文正文（留在单位系统里）。所以不做「笔记」「照片附件」「资料卡」，备注支持长文字和可点链接。
- **导出**：设置 › 数据与备份。JSON 完整备份（不含 AI Key、推送订阅、服务器口令）、Markdown 阅读版、CSV 待办表（带 BOM，Excel 直接打开）。手机走系统分享（先点「导出」准备好，再点「保存」，iOS 要求分享必须在点按时发起），电脑直接下载。文件名用英文。
- **周报草稿**（`data/report.js`）：通用五段——本周完成 / 推进中（附本周最后一条进展）/ 需协调（等谁、等了几天）/ 下周计划（下周结束前到期，含逾期）/ 材料收集（已交几份、谁没交）；每段按项目分组。只用已有的进展信息，不编内容。入口：负一屏「写周报」、标题含「周报」的待办详情。
- **待办状态**：未开始 / 进行中 / 等待他人 / 已完成。
- **项目归档**：可在「项目」页底部或项目详情里恢复，恢复时要定新的结束日期（默认今天 + 7 天），否则下次打开又会进入到期处理。
- **项目到期先收尾再归档**（决定 4 + 小规则 9）：过了结束日、待办都做完的才自动归档（打开应用时）；还有没做完的，首页出收尾卡（一次一个项目，结束早的先），项目详情顶部同样一块，项目页标「待收尾」。操作：顺延结束日（默认今天 + 7 天，不早于今天）/ 移到零星待办 / 一并完成（重复的不再生成下一次）/ 停止催办（有等待中的才显示；等待中的默认照常催办）。处理完没剩下的就归档。过了结束日的项目，详情里不再自动补排催办，要重新催点「已催」。
- **自动留痕**（第二阶段，需执行 005）：改状态、改截止、点「已催」各自动记一条进展（`todo_logs.kind` = status / due / nudged），详情里用浅色小字和手写的区分。改截止一律走 `todos.changeDue`，10 分钟内连着改只留一条。勾选完成后「撤销」会连同「完成」这条和自动生成的下一次一起撤回（不进最近删除）。周报「推进中」只认手写进展，「需协调」写「已催 N 次」；搜索不搜自动留痕。没执行 005 时不记，其余照常。
- **已催**（小规则 2）：等待一行的「已催」= 记一笔、丢掉待发的催办、从现在起按节奏重排，提示下次什么时候提醒你催。
- **改截止时提醒跟着改**：「截止前 N 分钟」按新截止重算（全天照 09:00 规则）；「到点」跟着新截止（全天 = 截止当天 09:00）；指定时刻的不动；已经过了的删掉，同一分钟只留一条；原来没有截止的按默认提醒排；逾期后往后挪，为原截止发过的提醒按同样意思再排一次。切换全天 / 有时刻同样重算。
- **列表范围**：`listTodos` 默认只读没完成的和近 14 天完成的；全部待办（搜索、显示已完成）、项目详情读全部，日历读截止在显示范围里的已完成，周报读那一周以来完成的。
- **日历节假日**：法定节假日标「休」、调休上班日标「班」（只标 `core/holidays.js` 里有数据的年份）。
- **套用历史任务**：复制联系人、待办（标题/子步骤/标签/优先级/重复）、材料收集清单；所有日期按「新开始日 − 旧开始日」整体平移；「第N届」自动 +1。
- **等待他人与催办**：等待对象可以是人/部门/科室/单位，默认从任务联系人中选。催办时间在 `core/schedule.js`：任务时间已过 < 50% 每 3 天，50%~80% 每 2 天，> 80% 每天；固定早上 9 点。
  - 落在非工作日顺延到下一个工作日的 09:00（2026-10-22 确认：不管展期，只管工作日）。
- **工作日**（`core/holidays.js`）：周一到周五，去掉法定节假日，加上调休上班的周六周日。用在催办顺延和「每个工作日」重复。节假日表按国务院办公厅每年的通知手工补一年（一般 11 月公布）；没有数据的年份只按周末算。
- **重复待办**：完成后按规则生成下一次（同一系列、同一天只会有一条没完成的，数据库唯一约束兜底）。补完逾期的那一期后，**今天这一期照常保留**（下一次 = 原截止日之后、不早于今天的第一期）；中间跳过的期数提示「跳过了 N 期」（`schedule.repeatSkipped`）。
- **提醒**：截止前（默认值在设置里改）、准时、指定时刻；早报默认 08:30、晚报默认 18:00，都可关闭。
  - 全天待办的提醒一律在早上 09:00：「截止前 N 天」= 截止日往前 N 天的 09:00；不足一天的（15 分钟、1 小时）= 截止当天 09:00。所有地方都用 `schedule.beforeDueAt()`。
  - 时刻已经过了的提醒一律不排（否则服务器会当成错过的提醒立刻「补发」）。
  - 全天待办的截止时间统一存当天 23:59。
- **记一条**（`components/capture.js`，首页下拉和手机底部「+」弹层共用）：
  - 多行输入框，内容多了自动长高；电脑回车保存、Shift+回车换行；手机用常驻的「保存」按钮。连按回车 / 连点保存只记一条。
  - 打字时自动存草稿（localStorage `wb-capture-draft`，项目详情里的输入框是 `wb-capture-draft:task:<项目id>`），收起、刷新、切页都不丢；保存成功才清掉。
  - 长文本（多行或好几句，如转发的微信通知）：第一句做标题，原文整段进备注。
  - 时间说法（`core/parse.js`）：「下班前」= 17:30；没说上下午的 1～6 点按下午算；「晚上12点」= 当天 23:59；只说日期 = 全天。
- **材料收集**：系统只生成催办文字，由用户复制后自己发，**不代发**。
- **AI**：可开关。关闭时所有功能照常可用，AI 入口自动隐藏，且不发出任何模型请求。AI 只做增强，不能成为任何功能的前提（代码在 `data/ai.js`）：
  - 标签推荐：快速记录与详情里，在本地常用标签之外补充 AI 建议（✦ 标记）；不接 AI 也可以用「＋ 自定义标签」/「＋ 标签」手动添加（带已有标签补全）；
  - 时间识别增强：规则解析（`core/parse.js`）之后，标题里还残留时间说法（「下班前」「月底」等）才请 AI 补充；AI 失败或超时（6 秒）保持规则结果；
  - AI 对话（`components/ai-chat.js`）：首页标题行 ✦ 打开（手机底部弹出、电脑居中）。只读，不改数据；对话只在本次打开期间保留，关闭即清空。
    - 知识库（`data/knowledge.js`）：把待办（含子步骤、进展、等待对象、待发提醒）、项目（含已归档、联系人）、材料收集（含已交/未交）、联系人整理成带编号的条目（T/P/C/K + id）；每次提问在本地按关键词二字组、人名/项目名、意图词（等/催、逾期、今天/本周、收集…）挑最相关的约 24 条 + 当前概况发给模型，不额外调用 AI。
    - 回答约束（系统提示 + max_tokens=320）：≤120 字、列举最多 5 条、每条 ≤25 字、只用加粗/编号列表；引用条目时带编号，界面渲染为 ↗ 链接，点开对应待办/项目/收集；数据里没有就说没有。
    - 快捷提问 Tips：「简报」「Top 5」（各受开关控制）、「供应商还有啥没回」「等谁最久」「材料没交齐」。
  - Key 存 `user_settings.llm_api_key`（只有本人可读），从不写进代码或仓库。调用链：同源代理 → 直连 → 平台免 Key 模型。

**平台约束（WorkBuddy 2026-10-20 答复）**：没有自定义环境变量（只注入 PORT）；服务常驻（http-service），但平台维护时可能重启 → 服务器不能把状态放在内存或磁盘。

**组成：**

| 部分 | 文件 | 说明 |
|---|---|---|
| 添加到主屏幕 | `public/manifest.webmanifest`、`public/icons/`（`node tools/make-icons.js` 生成） | iPhone 推送的前提：iOS 16.4+，从主屏幕图标打开 |
| Service Worker | `public/sw.js` | 只负责显示通知、点击打开对应页面；不做离线缓存 |
| 订阅 | `public/app/core/pwa.js` | 设置页「开启通知」→ 请求权限 → 订阅 → 存 `push_subscriptions`（每台设备一行） |

| 调度 | `server/scheduler.js` | 每分钟一轮；「先认领再发送」保证不重复；重启后 6 小时内的提醒补发，更早的只标记；早晚报超时 3 小时不补；催办发出后自动续排 |
| 数据访问 | `server/store-db.js` + `db/migrations/002_push.sql` | 服务器在 Node 里加载与前端相同的 SDK，以 anon 身份调用带「服务器口令」校验的 SECURITY DEFINER 函数 |
| 口令来源 | `server/keys.js` | 先找 `server/server-token.txt`（方案 B），没有就等管理员登录后由应用交接（方案 C） |

SQL 已在真实 Postgres（PGlite）里跑通全部迁移并验证：错误口令被拒、认领不重复、催办不重复排、早报当天只标记一次、推送密钥只能写一次、只有管理员能取口令、anon 读不到 `server_config`。

**发送失败重试、每日快照、心跳（第二阶段，需要 005）**
- 发送失败重试（用户确认：最多 3 次，宁可偶尔重复收到一次）：一条提醒有订阅、但一台设备都没送到时，服务器调用 `wb_reminder_failed`。有设备是临时失败（推送服务返回非 2xx、超时、断网）且不是催办 → 放回队列，2/4/6 分钟后重发，3 次后仍失败记为「没送达」（`failed_at`）；催办不重试（认领时下一次催办已经排上），直接记「没送达」；所有设备都已失效（404/410，订阅已删）→ 直接记「没送达」。用户没开通知（没有订阅）不算失败；有一台设备送到就算送达。早晚报不重试。重试中的提醒不受 6 小时补发窗口限制。
- 每日云端快照：调度每轮最后调用 `wb_daily_snapshots`，最多 10 分钟一次；每人每天（按用户时区）只存一份，保留 14 天，不含 AI Key、推送订阅、服务器口令。快照出错不影响提醒。
- 没执行 005 时：新函数不存在（PGRST202 / 42883），服务器只记一行日志，提醒照常发送（只是不重试、不记没送达）；快照暂停 6 小时再试。
- 出错不中断：某一条提醒或某一步数据库出错，只跳过这一条 / 这一步，本轮其余的提醒、早晚报、快照照常进行。
- 心跳：`GET /api/push/status` 除 `push`（on / locked / waiting / off）外，还返回 `lastTick`（最近一轮跑完的时间）、`lastOk`（最近一轮没有数据库错误的时间）、`snapshotAt`（最近一次快照调用成功的时间）、`startedAt`（本次启动时间），都是 ISO 时间或 null。只存在内存里，重启后为 null，第一轮在启动后 1～2 分钟内。不含错误内容和用户数据。设置页据此显示「提醒服务正常 · N 分钟前」。
- 服务器专用函数新增 `wb_reminder_failed`、`wb_daily_snapshots`。

### 8.1 服务器口令（平台无环境变量时的做法）

- 数据库表 `server_config`：开 RLS、无任何策略，前端读不到。存口令的 sha256（校验用）、口令明文（仅方案 C 用）、管理员 owner_id、推送签名密钥（服务器首次启动自动生成写入）。
- 服务器专用函数（`wb_claim_due` / `wb_schedule_nudge` / `wb_digest_candidates` / `wb_mark_digest` / `wb_remove_subscription` / `wb_server_vapid` / `wb_server_init_vapid`）第一步都校验口令；只返回推送必需的最少字段（标题、时间、状态、订阅），不返回 AI Key、备注等。
- 口令从哪来，两种方式都支持，**按部署自选**（面向部署者的完整说明与步骤：[部署与初始化.md](部署与初始化.md) 第二节）：

| 方案 | 怎么做 | 重启后 | 适合 |
|---|---|---|---|
| 口令文件 | `node tools/new-server-token.js` 生成 `server/server-token.txt` 并打印一条 SQL 交 WorkBuddy 执行；文件随部署（从 GitHub 部署时需仓库私有，并由部署者本人从 `.gitignore` 移除后提交） | 自动恢复，不漏推 | 自己用、项目只在自己手里 |
| 管理员交接（默认） | 什么都不用做。002 执行时库内自动生成口令，管理员 = 当时 `user_settings` 里最早的用户；管理员每次打开应用，应用自动把口令交给服务器（只存内存） | 暂停，直到管理员再打开应用，6 小时内的提醒随后补发 | 给同事部署、不想在仓库放密钥 |

- 接口：`GET /api/push/status`（on / locked / waiting / off）、`POST /api/push/unlock`（方案 C 交接，限流，校验通过才接受）。`off` = 本机调试，推送调度没启动（`WB_PUSH=1` 打开）。
- **重新部署 = 服务器重启**：管理员交接模式下推送会回到 locked。应用在「启动时」和「回到前台时（离开超过 30 秒）」都会自动交接，所以部署后管理员打开一次工作台即可恢复。

### 8.2 主屏幕 App 的生命周期（`core/lifecycle.js`）

- iPhone 会把主屏幕 App 挂在后台，再打开时不重新加载页面。所以回到前台时会：交接口令、重新拉数据、检查新版本。
- 下拉刷新（手机布局、页面顶部下拉）：只重新拉数据，不整页重载。
- 新版本提示：服务器启动时计算 `public/` 的指纹（`GET /api/version`）；指纹变了就在顶部提示「有新版本 · 点这里更新」，点了才整页重载。
- Service Worker 不做离线缓存，所以不存在「旧代码被缓存住」的问题；整页重载即拿到最新代码。
- **给同事部署**：见 [部署与初始化.md](部署与初始化.md) 第四节（不需要 GitHub；绝不复用别人的口令文件）。
- 换口令：重新运行 `tools/new-server-token.js` 并执行它打印的 SQL，旧口令立即失效。

## 9. 部署流程

1. 本地自检通过（§3）。
2. 更新部署所用的代码：让 WorkBuddy 从你的 Git 仓库拉取最新代码，或把项目文件夹拷到 WorkBuddy 部署所用的目录覆盖。
3. 如有新迁移文件，让 WorkBuddy 按编号逐条执行（`workbuddy_cloudservice_db_exec_sql`，mode=migrate）。

5. 线上验证：微信登录 → 新建待办 → 改状态 → 刷新后数据还在。
